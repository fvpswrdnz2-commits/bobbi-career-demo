## 2. 第一版必须完成的范围

### 2.1 用户、角色与运营

- [x] 学生端和前辈端位于同一个微信小程序，同一微信用户可同时具有学生和前辈双角色。
- [x] 所有用户默认具有学生能力；受邀前辈审核绑定后增加前辈能力，暂停前辈身份不影响学生能力与历史订单。
- [x] 波比使用独立网页后台；第一版只有一个超级管理员，不开放后台注册或多级管理员。
- [x] 旧前辈由波比后台导入，可先不绑定微信账号且免交证明材料。
- [x] 新前辈只能通过有效邀请提交资料，至少上传一份证明材料，经波比审核、配置价格和档期后发布。

### 2.2 前辈资料与搜索

- [x] 投稿编号与小红书编号一致且唯一，支持投稿编号直达。
- [x] 支持标签组合筛选；同维度多选取并集，跨维度取交集。
- [x] 支持基于简单标签与别名词典的一句话搜索，不调用生成式 AI。
- [x] 非编号搜索采用“求职路径智能匹配”：目标方向 40%、经历深度 30%、教育背景 15%、可辅导内容 15%，未表达维度不计入分母。
- [x] 方向关系按完全相同 100%、同赛道 70%、同行业不同岗位 40%、明确弱关联 20%、无关 0%计算；经历深度区分最终去向、Offer、终面、面试、过简历和实习。
- [x] 同分依次按完全匹配标签数、经历深度、辅导内容、资料完整度、轮换曝光值和投稿编号；结果展示 2—4 条可追溯的确定性匹配理由。
- [x] 首页使用确认的轻松 Slogan 和一个方向分散、同方向轮换的基础列表，不设置“波比精选”或“最近上新”，简介不拼接可约时间。
- [x] 档期、最早可约时间和套餐时长不参与首页或搜索排序，只在选定人选和套餐后的预约环节校验。
- [x] 搜索、排序和匹配理由只读取允许公开的档案字段，不读取档期、证明材料或预约方资料。
- [x] 第一版标签词典只保存当前标准名、维度、业务大类和别名，不建立词典版本系统。

### 2.3 档期、预约与支付

- [x] 可售档期由波比在后台维护；新增受邀前辈填写的可预约时间偏好只供波比参考，不直接生成可售档期。
- [x] 首次预约只允许未来 7 天内且距咨询开始至少 6 小时的档期。
- [x] 以 30 分钟为最小单位，支持 30、60、90 分钟固定套餐；60/90 分钟必须连续占用 2/3 个时段。
- [x] 待支付订单锁定档期 15 分钟，超时关闭并释放；并发占位由服务端事务和数据库唯一约束裁决。
- [x] 预约时必须一次性提交简历和非空咨询问题，未提交不得支付。
- [x] 价格由波比后台维护，客户端金额不可信；订单保存创建时的整数分价格快照。
- [x] 使用微信支付 API v3；以验签后的服务端回调或主动查询结果作为支付事实，所有处理幂等。
- [x] 付款成功自动接单、确认档期、开放对应前辈的材料访问并生成唯一会议待办。

### 2.4 会议、履约与通知

- [x] 腾讯会议由波比在外部人工创建；后台人工录入或更新会议号、可选密码和链接。
- [x] 支付后会议未更新时，小程序显示“稍后查看会议链接”；保存后显示“会议信息已更新”。
- [x] 系统发送站内消息和经授权的微信订阅消息；咨询前 24 小时和 2 小时安排有意义的提醒。
- [x] 咨询前 2 小时仍缺有效会议时，生成后台高优先级待办，并由服务端向配置的波比手机号发送紧急短信。
- [x] 到达开始时间进入咨询中，到达结束时间双方订单直接显示已完成。

### 2.5 改期、取消、退款与人工结算

- [x] 学生和前辈各有一次免费改期额度并分别计数；同一方第二次按原始订单金额 10%处理，第三次只能取消。
- [x] 改期必须在当前约定开始前至少 2 小时发起并完成对方确认；新时间位于确认时起未来 7 天内，且不受首次预约 6 小时限制。
- [x] 对方确认前原时间继续有效；新旧档期原子切换。学生第二次改期需补付 10%，前辈第二次改期向学生退 10%。
- [x] 学生取消退原始订单 90%，已支付改期费默认不退；前辈取消退原始订单及学生改期补款的全部金额。
- [x] 所有支付与退款只追加或冲正；最终净收入等于全部有效支付减全部成功退款。
- [x] 系统按最终净收入自动计算前辈 80%、波比 20%；波比在平台外线下付款，只在后台汇总、登记和导出人工结算记录。
- [x] 退款处理中或账务异常订单不得结算；结算状态独立于小程序订单的“已完成”状态。
- [x] 前辈端不设置结算中心，不展示待结算、预计结算、已结算状态或金额。

### 2.6 数据、隐私与运营

- [x] 前辈只保存一份档案，以字段权限区分公开资料和仅超级管理员可见资料。
- [x] 前辈证明材料仅超级管理员可见；第一版不强制逐项核验，新前辈至少一份、旧前辈豁免。
- [x] 学生简历支付前仅本人和超级管理员可见；支付后只向对应前辈开放。
- [x] 咨询结束 7 天后撤销前辈对简历的访问；90 天后删除原始简历。
- [x] 记录统一用户、搜索、浏览、预约、支付、完成和复购所需的最小事件；第一版业务类型固定为 `ONE_ON_ONE_CONSULTATION`。
- [x] 小程序面向用户的称谓遵循昵称、标签、“对方”“我的资料”等规则，不改变内部角色模型。

## 3. 第一版明确不做

- [x] 不做群面报名、自动组队、群面练习或求职讲座页面与流程。
- [x] 不做渠道码、渠道归因、首次来源、最近来源或分渠道转化漏斗。
- [x] 不做公开申请成为前辈、学生与前辈自由聊天或求职内容社区。
- [x] 不做多级管理员、前辈自行维护档期、多种咨询服务、独立套餐定价、咨询续时或补单。
- [x] 不做腾讯会议 API 自动创建、修改或取消会议。
- [x] 不做微信支付自动分账。
- [x] 不做销量、排行榜、复杂评价、优惠券、会员、积分或营销裂变。
- [x] 不做售后反馈、售后工单或 24 小时售后期。
- [x] 不做个性化推荐、机器学习排序、生成式 AI 简历分析/咨询总结、Elasticsearch、向量数据库或 RRF。
- [x] 不预建群面/讲座的数据模型、角色、页面或运行分支；只保留统一用户 ID、订单 `business_type` 和事件 `business_type` 三个低成本扩展点。

## 4. 强制安全与可靠性要求

- [x] 金额、角色、订单状态、档期有效性和文件权限全部由服务端判断，客户端输入不得作为事实。
- [x] 所有金额以整数“分”保存；数据库时间使用 UTC，界面按 `Asia/Shanghai` 展示。
- [x] 支付、退款、改期确认、档期占位、外部回调和定时任务必须幂等。
- [x] 同一档期的并发竞争由数据库事务和唯一约束保证，不能依赖页面状态。
- [x] 微信支付私钥、API v3 密钥、商户证书、数据库口令和长期云凭证不得进入客户端、源码、文档或日志。
- [x] 简历、证明材料和结算凭证存入私有对象存储；禁止永久公开 URL，每次访问先重新鉴权再签发短时链接。
- [x] 日志不得包含简历正文、证明内容、短时文件链接、完整联系方式、会议密码或支付秘密。
- [x] 查看敏感材料、审核、强制改期、金额修改、退款、会议替换和结算登记必须写入不可由普通业务删除的审计日志。
- [x] 订单状态变化与通知事件使用同事务 Outbox；通知失败不回滚交易事实，可安全重试且避免重复轰炸。
- [x] 支付、退款、会议录入、缺会议、文件删除和结算异常必须形成可追踪后台待办。
- [x] local、staging、production 的数据库、文件、微信配置和密钥完全隔离；真实资料不得复制到测试环境。
- [x] 上线前必须准备隐私政策、用户协议、咨询服务规则和退款规则，并记录用户同意版本。
